Building with Codex + the Design Brain

The full setup — from a clean machine to generating Orbit UI with Codex.

✦ Hold onto this: Obsidian and Codex are two separate tools doing two separate jobs, joined by one export step. You build in efficio-orbit with Codex; you edit the brain in Obsidian. Never build in Obsidian; never run Codex in the vault.
🟪

Obsidian + the Vault

Where the brain is authored & stored (on OneDrive).

Your job: edit the brain
🟦

efficio-orbit (git)

The Orbit code + where you build. The brain is exported here.

Your job: build UI
🟢

Codex

The AI. Run it inside efficio-orbit; it auto-reads the brain.

Its job: generate to spec
📚 Vault— export → 📦 efficio-orbit / AGENTS.md— reads → 🟢 Codex builds

The mechanism: there's no plugin. Codex uses the brain because AGENTS.md is present in the folder it runs in. The export puts it there.

PART A

One-time setup

do once per machine
1

Obsidian + the vault

Install Obsidian → Open folder as vault → point it at …/OneDrive-Efficio/Orbit Design Brain. Then in Finder, right-click the folder → OneDrive → Always keep on this device.

2

The codebase

git clone <efficio-orbit repo url>   # if you don't already have it
cd <path-to-efficio-orbit>
npm install
3

Codex

Install Codex per your org's setup.

4

Put the brain into the repo (the export)

cd "~/Library/CloudStorage/OneDrive-Efficio/Orbit Design Brain"
python3 tools/export_brain.py --target <path-to-efficio-orbit> --profile all --dry-run   # preview
python3 tools/export_brain.py --target <path-to-efficio-orbit> --profile all             # apply

Then git commit & push in efficio-orbit.

⚡ Teammate shortcut: if someone already committed the export, skip step 4 — git pull gives you the brain for free.
PART B

Each time you build something with Codex

1

Get the latest brain

git pull in efficio-orbit. (Only re-export if YOU changed the vault.)

2

Open the repo in Terminal

cd <path-to-efficio-orbit>
3

Start Codex

codex
4

Confirm it loaded the brain

Ask: "Before writing code, summarise the Orbit constraints you'll follow." It should mention tokens-only, platform-first, the Definition of Done. If not — wrong folder, or not exported.

5

Give the task — and name the platform

"Build a Connected Platform workspace card for X." If it's an assigned sprint feature: "…following discovery/<initiative>.md."

6

Let it build to spec

It reads the relevant design-brain/ files (routing table in AGENTS.md §3) — platform profile, defaults.md, the component/pattern contract — and builds to tokens, contracts, defaults.

7

Validate

Check the Definition of Done (AGENTS.md §5): all states, both themes, both densities, WCAG AA, no anti-patterns. Thorough pass: "Now run the design-reviewer on this." A blocker means not done.

8

Feed back

If it got Orbit wrong and you fixed it, update the vault file in Obsidian — then re-export (Part A, step 4). The brain sharpens every time.

OBSIDIAN

Where Obsidian fits

📖

Teach the AI — don't build in it

Open Obsidian only to edit the brain: write a discovery pack, fix a contract, correct something the AI got wrong. You never build UI in Obsidian. Think: Obsidian = teach the AI · Codex-in-the-repo = the AI builds.

PER SPRINT

The Discovery flow

📝 PM writes the 4D Word doc→ ✂️ you distil it into discovery/<initiative>.md in Obsidian→ 🔁 re-export→ 🟢 Codex reads it when it builds
REFERENCE

Quick command reference

# 1) Export the brain into the repo (run from the vault)
cd "~/Library/CloudStorage/OneDrive-Efficio/Orbit Design Brain"
python3 tools/export_brain.py --target <repo> --profile all

# 2) Share it (in the repo)
cd <path-to-efficio-orbit>
git add -A && git commit -m "Update Orbit Design Brain export" && git push

# 3) Build (in the repo)
codex            # it auto-loads AGENTS.md → give it the task + platform
★ The one rule: edit the Vault, never the exported copy — then re-export. That's what keeps the whole team's AI in sync.
