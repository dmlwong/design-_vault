How to use the Orbit Design Brain

Your team's shared source of truth for building Orbit UI — with AI in the loop.

✦ The promise: any AI tool (Claude Code, Codex) produces Orbit-correct UI — not a generic look — because the rules, components, and patterns are already in its context. Your job is to point it at the right parts and check the result.

Two ways you'll use it

Build with AI · engineers + designers

🟦 Use it to generate UI

You ask an AI to build a screen. The brain is in its context, so it builds to Orbit's tokens, components, and patterns. You guide and review.

You edit the vault when the system changes or the AI gets something wrong. Edit the vault, never the exported copy.

Building a screen with AI — the 5 steps

1
Start · pull context

Start in the brain, not the design tool

The AI auto-loads AGENTS.md. Tell it the task and have it read what's relevant — the platform profile, defaults.md, the component/pattern contract, and the discovery/ pack if it's an assigned feature. If you start with an empty context, you're not using the model — you're working next to it.

2
Identify · platform first

Which platform is this?

Connected Platform (internal Efficio) or Orbit / Client Connected Platform (external client)? The AI must know before it designs anything — they look and behave differently. If it's unclear, ask.

3
Design · build to spec

Build to the contracts & defaults

Tokens only — never hardcode. Use the real Orbit components, the defaults.md choices, and the pattern composition (e.g. work-card). No freelancing — when unsure, use the default.

4
Validate · definition of done

Check it against the Definition of Done

All states (loading / empty / error / disabled), both efficio + orbit themes, comfortable + compact density, WCAG 2.2 AA, Orbit voice, no anti-patterns. Delegate a pass to the design-reviewer. A blocker means not done.

5
Feed back · keep it true

Fix the brain, not just the output

When the AI gets Orbit wrong and you correct it, update the relevant vault file so the fix sticks for everyone. The brain is living memory — it sharpens every sprint.

The non-negotiables

🧭
Identify the platform firstCP (internal) vs Orbit-client (external). Never blend them.
🎟️
Tokens onlyNever hardcode a colour, spacing, radius, font, shadow. A literal is a defect.
📄
Use the contract, not your imaginationRead the component/pattern contract before building.
🚫
Match Orbit, not the defaultThe generic ShadCN/Tailwind look is the #1 quality risk.
♿
WCAG 2.2 AA is the floorContrast, keyboard, visible focus, status not by colour alone.
📊
Density is first-classComfortable by default, compact supported. Tables/lists must stay legible.
🔁
Every state designedDefault, hover, focus, disabled, loading, empty, error — not just the happy path.
✋
Stop & ask on conflictsWhen a request fights the rules, ask — don't silently resolve it.
