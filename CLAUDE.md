## Claude Code Specifics

- The detailed brain (`tokens.md`, `components/`, `motion.md`, etc.) is not auto-loaded.
  Read the relevant file before acting; the routing table in `AGENTS.md` tells you which.
- For repeatable design work, prefer the skills in `design-brain/skills/`:
  - `component-contract` — build/refactor a component to its written contract.
  - `extract-contract` — generate a contract from existing source.
  - `port-to-orbit` — bring an external/Lovable prototype onto Orbit tokens/components.
- For multi-component or full-screen work, delegate review to `design-reviewer`
  (`design-brain/agents/design-reviewer.md`). A blocker means not done.

## Build / Test Commands

Run from `the efficio-orbit repo` unless stated otherwise.

- Install: `npm install`
- Dev docs: `npm run dev:docs`
- Dev prototypes: `npm run dev:prototypes`
- Build all workspaces: `npm run build`
- Build component package: `npm run build:orbit`
- Typecheck component package: `npm run typecheck:orbit`
- Test components: `npm run test:components`
- Lint: `npm run lint`
- Static design-system audit: `npm run audit:design-system`
- Benchmark accessibility artifact: `npm run bench:a11y`
- Browser visual accessibility pass: see
  `design-brain/_benchmarks/accessibility-artifact-process.md`
- Regenerate generated design docs: `npm run build:design-md`
- Export Orbit style guide: `npm run export:style-guide`

## Repository Facts

- Canonical Design Brain authoring home: this Obsidian vault.
- Product repo copies are generated by `tools/export_brain.py`; do not hand-edit them.
- Orbit component library: `packages/orbit/src`.
- Token bundle: `packages/orbit/tokens.css`.
- Token source files: `packages/orbit/styles/tokens/`.
- Orbit theme override: `packages/orbit/styles/tokens/themes/orbit.css`.
- Prototype app: `apps/prototypes`.
- ClauseIQ prototype: `apps/prototypes/components/feature/clauseiq/ClauseIQPrototype.tsx`.
- Generated design documentation: `DESIGN.md`.
- Edit generated design prose in `design-md/prose/DESIGN.prose.md`, then run `npm run build:design-md`.
- Explore prototypes live in `discovery/prototypes/<slug>/`: a governed record whose
  `brief:` key points back at the brief (that link is what lights the concept's *Explored*
  stage), plus the self-contained prototype HTML. The HTML is withheld from product-repo
  exports; the record travels. Template: `discovery/prototypes/_TEMPLATE-record.md`.
- Definition matrices are authored in Excel and kept canonical as markdown:
  `tools/matrix_xlsx.py export|import|template` moves between the two, and `--check`
  (in CI) asserts the round trip is exact. Never hand-edit a generated journey-flows page —
  edit the matrix and rerun `tools/build_journey_flows.py`.
- The "Concepts in flight" section of the health report is derived from artifacts on disk;
  a stage lights only when the file proving it exists. It is generated — do not hand-edit
  `HEALTH.md` or `vault-health.html`.
- Vault health report: `tools/vault_health.py` (run from the vault root with python3)
  regenerates `HEALTH.md` (full internal report), `vault-health.html` (the stakeholder
  page), and the trend in `tools/health_history.json`. All three are generated — do not
  hand-edit. CI runs it daily.
- `vault-health.html` is the **full internal view**: it names product surfaces, the
  design-system owner, and the repo path of every catalogued item, because telling a
  reader a spec exists without telling them where it lives is useless. It is therefore
  marked `protected` in `tools/site-manifest.json`, which means it skips the public
  sanitiser entirely and is instead encrypted at publish time with the `SITE_PASSPHRASE`
  secret. If that secret is absent the page is **omitted from the published site** rather
  than published in the clear — so a missing live health page is the designed behaviour,
  not a broken build.
