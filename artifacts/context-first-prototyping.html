Orbit Design Brain · Proposal

Capture the context, then generate the prototype

Today Lovable prototypes arrive with no record of the concept behind them, so teams reverse-engineer intent from pixels. The fix isn't a better prototype — it's capturing the problem, journeys and outcomes at intake, then letting the vault generate a prototype grounded in how Efficio actually works. This sketches the intake form and the end-to-end flow.

01

The shift

Today

Prototype first, context never. Intent is trapped in the screens; every downstream team guesses, and the guesses disagree.

→

Proposed

Context first. A short structured brief is captured up front and becomes the seed — the prototype is an output of the intent, not a substitute for it.

03

End-to-end flow

From a stakeholder filling the form to a winning concept becoming real on Orbit. Colour marks the funnel: Explore (diverge, throwaway, not Orbit-bound) then Port (converge, on-system).

1
Stakeholder

Fill the intake form

The structured brief — problem, user, journey, outcomes, constraints. Replaces the context-free hand-off with a captured intent.

2a
Rule · deterministic

Completeness check

A plain validation rule — the same kind already in the vault's lint tools. Required fields present, platform valid, journey has real steps, no placeholder text. Free, instant, and it stops empty briefs before any compute is spent. Fails fast back to the stakeholder.

2b
Brief-reviewer · AI

Review the brief — a gate, not a funnel

An AI reviewer judges what a rule can't: is it a problem or a solution in disguise, is the outcome testable, is it one bet, is it even buildable? It returns a verdict — Ready / Needs work / Blocked — with specific gaps and suggested rewrites. See the rubric below for the standard it checks against.

Verdict loop: anything short of Ready returns to the stakeholder before generation — the cheapest place to fix intent. A documented standard, a verdict, an owner: that is the governance this adds.
🛡️

The garbage-in guard

People jump to a Lovable prototype precisely because they can't yet articulate the problem. The rule + reviewer make a good brief the easy path — worked examples, required fields, and the vault naming exactly what's missing.

3
Vault

Ground the brief in Efficio context

The brief is combined with what the vault knows: design patterns, tokens & components today — and, as it fills, the product context (tech reality, personas, domain, vision).

Dependency: output quality is capped here. The form raises the floor; the Efficio Context Pack raises the ceiling. Thin context → plausible-but-generic result.
4
Explore

Generate the concept prototype

The /explore skill runs: Frame → build a genuinely interactive artifact → verify it works → adversarial critique. Fast, clickable, not Orbit-bound.

Fork to decide — Lovable's role: either the vault seeds a Lovable prompt (stakeholders stay in their tool) or the vault generates the prototype directly and Lovable drops out. Pick one.
5
Human

Steer the bet

A person reviews the running concept, its critique, and the flagged gaps, then decides: keep, redirect to a different bet, or kill. The human owns the bet — always.

6
Port

Make the winner real

A concept worth keeping enters the Port funnel (port-to-orbit) to become Orbit-correct, tokens-only, production-leaning. This is where the existing vault already shines.

The self-improving loop: every gap /explore flags at step 4 becomes the backlog for the Context Pack. Intake → surfaces missing context → fills the vault → the next intake is sharper. The system gets better with use.
04

The intake gate & brief rubric

Governance is a written standard plus a verdict plus an owner. Two layers do the checking — a cheap rule, then a judgment call — and the reviewer scores every brief against the rubric below.

Layer 1 · rule

Structural validation

Deterministic, free, runs on every submit. Catches empty and malformed briefs — but can't tell a good brief from a well-formatted bad one.

reuses the vault's lint pattern
Layer 2 · AI agent

brief-reviewer

The upstream sibling of design-reviewer: it reviews the input before anything is built, judging clarity, testability and fit against the rubric.

verdict → Ready / Needs work / Blocked
1Problem, not solution
States a user pain, not a pre-chosen feature. Red flag: "add a filter." Good: "reviewers can't spot changed clauses."
2One primary user & moment
A single user in a specific situation. Red flag: "all users, everywhere."
3One testable bet
A single core flow to prototype. Red flag: five journeys bundled into one ask.
4Falsifiable outcome
Success is observable or measurable. Red flag: "make it more intuitive."
5Evidence over appeal
Grounded in a real signal, not novelty. Red flag: "a competitor has it."
6Scope is fenced
Explicit non-goals. Red flag: unbounded — everything is in scope.
7Feasibility acknowledged
Constraints named, or unknowns flagged. Red flag: assumes data or an integration that doesn't exist.
8Context sufficiency
The vault (or the brief) supplies enough to build well. Red flag: needs context the vault lacks → routes a task to the Context Pack.
Ready

Meets the bar. Proceeds to grounding and generation.

Needs work

Fixable gaps. Returns to the stakeholder with specifics — the common early outcome.

Blocked

Fundamental — not a real problem, or missing context/feasibility. Escalates to a human owner.

✓
Write the rubric down. The standard above is the artifact — an agent without it reviews inconsistently. This makes reviews auditable and repeatable.
⤺
Human override, with a reason. Governance is accountability, not a locked door. A stakeholder can override a verdict — the reason is logged.
↑
Manual → proven → encoded. Run the rubric by hand on real briefs first; encode the agent only once it earns it — exactly how the vault's other agents were promoted.
▲
Feasibility depends on the Context Pack. Criterion 7 is only as strong as the tech reality in the vault — the same ceiling as generation.
05

Two forks — now decided & built

Both were product calls; both are locked, and the pipeline is built to draft (form, rubric, template, brief-reviewer agent, routing). Rubric piloted on three briefs — verdicts matched pre-registration.

Decided ✓ · Lovable

Generate + seed

The vault generates the prototype via /explore (primary), and also emits a context-rich Lovable seed prompt.

Stakeholders who want to keep iterating in Lovable start from grounded context, not a blank canvas — a projection of the brief, not a second source of truth.
Decided ✓ · Funnel

Explore, then Port

The form → prototype is an Explore output: fast, testable, not Orbit-bound.

A winner then enters the Port funnel to become Orbit-correct. The seam is kept — one pass never does both.
Proposal for discussion · builds on the existing /explore skill and the Efficio Context Pack.
The form is the front door; the Context Pack is the fuel. Both are needed for output that feels like real Efficio.
