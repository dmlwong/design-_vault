Two audiences, two tools

Authors write the vault. Consumers never touch it.

The entire sharing model rests on one separation: people who shape the design guidance work in the vault; everyone (and everything) that builds UI reads a generated, read-only copy inside their own repository.

Authors edit the vault

Design · Product · Product owners

  • Work in Obsidian on a checkout of the vault repository — the single canonical copy.
  • Low-risk notes are edited directly; governed files (tokens, component and pattern contracts, the always-on rules) go through a change request approved by a design-system owner.
  • Every push is verified by CI: link integrity across all 97 documents and a required-files check.

Consumers read the export

Engineers · Claude Code · Codex · Lovable

  • Get the brain as a generated export inside their product repo — pulled with the code, no extra tools or licences.
  • AI tools load it automatically and follow the tokens-only, platform-first rules when generating Orbit UI.
  • The copy is disposable and never hand-edited; it carries a generated-export notice.
  • Lovable is the one exception: it receives a purpose-built projection pasted into its knowledge base.

The flow

From an edit in Obsidian to correct UI in production repos

Five stages, one direction of travel — with a feedback loop that makes the brain sharper every sprint instead of letting it rot.

1 · Author

Edit the vault

A designer or PM updates a token note, contract, pattern, or discovery pack in Obsidian.

2 · Govern

Owner approval

Governed files ride a change request; a design-system owner approves before merge.

3 · Verify

CI checks

Automated link check, required-files check, and a drift check that fails loudly if any copy differs from the vault.

4 · Export

Generate the packs

The exporter writes agent-ready copies into each product repo. Restricted material is excluded by default.

5 · Build

UI gets made

Engineers and AI tools build Orbit UI against the brain — same rules, every repo, both platforms.

When the AI gets Orbit wrong, the correction is made in the vault — so the fix becomes true for every team, permanently
The one rule: edit the vault, never the exported copy. If that holds, drift is structurally impossible — the repo copies are always reproducible from the source, and CI catches anyone who forgets.

Confidentiality by default

What travels with the export — and what stays home

Travels to every product repo

  • The always-on rules and routing (what AI tools must obey)
  • Design tokens, defaults, and interaction heuristics
  • All component contracts and page patterns
  • Golden examples with reference code
  • Platform profiles for both products
  • Skills and the design-reviewer agent for Claude Code

Stays in the vault

  • Platform screenshots (18 captures, pending sanitization review)
  • Private work-in-progress notes and internal state docs
  • Governance records, audits, and review history
  • Archived and superseded material

Exclusion is enforced by the exporter itself, not by convention — restricted content can only be included with an explicit flag after owner approval.

Access & cost

What it costs to share: almost nothing

Obsidian is free for commercial use, and consumers need no software at all — the brain reaches them through the repositories they already work in. The only question is how authors connect.

$0 — no subscriptions

Path A — Git-connected authors Recommended

Authors clone the vault and open it in Obsidian. Changes travel through pull requests, so governance and CI gate every edit automatically.

  • Strongest integrity: nothing lands unreviewed
  • Full version history, forever
  • Works today — this is the current setup
$4 / author / month — Obsidian Sync Standard

Path B — Add Sync for non-git authors Open decision

For contributors who won't touch git: each needs their own Sync seat; one owner hosts the shared vault and invites the rest. Git remains canonical via a sync-to-git bridge.

  • No git skills needed to contribute
  • Caveat: Sync bypasses review — the bridge keeps CI in the loop
  • Consumers still pay nothing, on either path

Getting started

Onboarding is measured in minutes, not weeks

A new author

≈ 30 minutes to productive

  1. Get access from a design-system owner and clone the vault.
  2. Open it in Obsidian — "Open folder as vault." Personal workspace state stays local.
  3. Read three files: the README, the always-on rules, and the current-state note.
  4. Edit by the rules: direct edits for low-risk notes; change requests for governed files.

A new consuming team

One export, then it's just git

  1. Run the exporter against the product repo (preview first, then apply).
  2. Commit the export — every teammate now gets the brain via git pull.
  3. Wire the drift check into the repo's CI so the copy can never silently diverge.
  4. Verify the brain loaded: ask the AI tool to summarise the Orbit constraints before its first build.
