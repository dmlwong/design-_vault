# Concept briefs — intake for the `explore` skill

Structured intent captured at the start of a delivery cycle, before any prototype exists.
A brief seeds the `explore` skill; it is the fix for context-free Lovable hand-offs.

## The flow

1. A stakeholder fills `tools/intake-form.html` (validates in-browser, generates the
   brief markdown).
2. They send it to the design-team intake owner, who commits it here as
   `<YYYY-MM-DD>-<slug>.md` (from the template `_TEMPLATE.md`).
3. The owner runs the `brief-review` task (`design-brain/routing.json`) — the
   `brief-reviewer` agent scores it against `design-brain/brief-contract.md` and returns
   **Ready / Needs work / Blocked**, logged in the brief's `## Gate log`.
4. A **Ready** brief feeds `explore`; a winning concept graduates to a full discovery
   pack (`discovery/_TEMPLATE.md`).

## Rules

- One brief per file. Filenames: `<YYYY-MM-DD>-<slug>.md`.
- Briefs are `status: draft` on submit, `in-review` in the gate, `stable` when Ready.
- The standard is `design-brain/brief-contract.md`; the reviewer is
  `design-brain/agents/brief-reviewer.md`.
