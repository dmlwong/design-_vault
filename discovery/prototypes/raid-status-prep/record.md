# Prototype record: PM status-prep view (RAID & commentary)

**Brief:** `discovery/briefs/2026-07-21-surface-the-latest-raid-commentary-before-a-pm-status-review.md`

## Provenance

**Reconstruction — owner-approved 2026-08-05.** The original explore run (2026-07-21)
delivered a Claude Artifact that was session-private; no file, URL, or artifact id was
recorded anywhere in the vault, so the original build is unrecoverable. This file was
rebuilt to the feature list the brief itself records in its Explore outcome section —
surfaced RAID + commentary with author and timestamp, filter by type, a
changed-since-last-review toggle and hero stat, a since-last-review divider, expandable
change history, and a flag → "to update before the meeting" tray.

Treat it as faithful to the *described* behaviour, not as the original bytes. It exists so
the Concept Pack's fourth deliverable is inspectable rather than remembered — and the loss
that made it necessary is why archiving is now a non-negotiable step in the `explore` skill.

## Verification

Driven headless with Playwright against the local file (Chromium), 2026-08-05:

- Type filters — "Risks" narrows 8 items to 2, every rendered item carries the matching type
- Changed-since-last-review toggle — narrows to the 4 changed items; hero stat reads 4 of 8
- Divider — both groups render ("Changed since last review" / "Unchanged since 22 Jul")
- Change history — collapsed by default, expands on click, `aria-expanded` tracks state
- Flag → tray — flagging adds the item to the tray, hero "flagged" count follows, the tray's
  empty state hides, and remove-from-tray returns it to zero
- Themes — the root `data-theme` flips between `efficio` and `orbit` and back
- Console clean: zero errors, zero failed requests (no network use — the file is self-contained)

## What it demonstrates

That a PM can answer "what changed since last period, and who changed it" without opening
the old modal or an offline tracker — the brief's countable outcome, made clickable. The
diff toggle plus the hero stat are the whole bet in one interaction: the prototype is only
useful if that number is trustworthy.

## Known gaps / critique pointers

The blind critique in the brief stands, and this rebuild does not answer it. The load-bearing
question — whether CP actually stores per-field edit history and author attribution — remains
unverified, which is why the concept's status is *not ready for Port*. Note the sample data
here *assumes* that history exists: every "changed" flag and every change-history row is
invented, and that assumption is precisely what a real PM session must test. "Changed" is
also implemented as a fixed review boundary (22 Jul), which is only one of the two competing
definitions the critique names. See the brief's Explore outcome for all three kill-risks.
