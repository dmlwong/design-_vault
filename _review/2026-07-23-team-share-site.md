# Team-share site — publishing the living tools to one link

> How the intake form and the health dashboard reach the team as **one public URL**,
> with no web app to run. The site is *generated* from the vault by
> `tools/build_site.py`; you never hand-edit it. This complements
> `_review/Team Sharing Setup.md` (which covers authors and consuming repos) — that doc
> is for people who edit the brain; this one is for stakeholders who just use the tools.

## What ships, and what deliberately does not

The site is only the surfaces that are **safe on an anyone-with-the-link URL**:

| On the site | Not on the site |
| ----------- | --------------- |
| The hub (`index.html`) | One-off concept prototypes |
| Concept Brief Intake (`intake-form.html`) | Pipeline / vault explainer decks |
| Vault Health (`health.html`, already sanitized) | Anything naming a specific product surface |

One-off prototypes and explainers stay as **private Claude Artifacts**, shared per person
via the page's **Share** button. They are point-in-time deliverables, not living tools —
they don't belong on a standing public link. The manifest of what *is* on the site lives
in `tools/site-manifest.json`.

## The one thing to get right: the exposure gate

The intake form's source (`tools/intake-form.html`) names real product surfaces and the
company — the same names the health page keeps private. **The public build removes them**:
`build_site.py --public` runs a sanitiser (product surfaces → functional labels, company →
"the platform") and then **refuses to build if any blocked name survives**. So the site
CI publishes cannot leak those names — a leak is a failed build, not a quiet mistake.

- **Preview what the public sees:** `python3 tools/build_site.py --out site --public`
  then open `site/intake-form.html`. Surfaces read as *Contract workflows, Market
  intelligence, Sourcing analytics, RFP authoring* — generic on purpose.
- If you decide the real surface names are fine on a public URL, that is a **governed
  decision** (same policy as the health page's platform-profile exclusion). Change
  `SANITISE`/`BLOCKLIST` in `build_site.py` with owner sign-off — don't work around it.

Everything the tools do runs in the visitor's browser; **nothing typed into the form is
sent anywhere.** There is no backend and no data collection to reason about.

## Going live (one-time owner setup)

The publish mechanism already exists in `.github/workflows/vault-integrity.yml` (the
`health` job's *Publish stakeholder site* step) and reuses the health page's companion
repo. It stays **dormant until a token is set**, so nothing is public by accident.

1. **Create a public repo** `dmlwong/vault-health` (or reuse it if the health page already
   uses it). Public = "anyone with the link". *(The GitHub integration can't create repos —
   this is a manual owner step.)*
2. **Enable GitHub Pages** on that repo: Settings → Pages → deploy from `main`, root.
   Note the URL (e.g. `https://dmlwong.github.io/vault-health/`); it's already recorded as
   `canonical_url` in the manifest.
3. **Add the secret** `HEALTH_PAGE_TOKEN` to *this* repo (Settings → Secrets → Actions) — a
   token with push access to the public repo. Its presence is what turns publishing on.
4. **Confirm the exposure gate** (above) is how you want it before the first publish.
5. The daily health job (06:00 UTC) then rebuilds and pushes the site on every run; it also
   publishes on pushes to `main`. To publish immediately, re-run the *Vault integrity*
   workflow on `main`.

To preview locally without any of this: `python3 tools/build_site.py --out site --public`
and open `site/index.html`.

## Changing the site

- **Add/remove a tool or edit copy:** edit `tools/site-manifest.json` (data), not the
  generator. Only add a surface once it's proven safe for a public link.
- **The form or health page changed:** nothing to do — the next publish rebuilds from
  source. The health page is regenerated by `tools/vault_health.py` in the same job.
- **Never hand-edit the published files** in the companion repo; the next run overwrites
  them.
