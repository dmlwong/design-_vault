Using the Design Brain — Step by Step

How to build Orbit UI with an AI tool (Codex / Claude Code) using this brain + the efficio-orbit design system.

✦ The core principle: there's no plugin. An AI tool uses the brain when AGENTS.md is present in the folder it's working in — it reads it automatically. Author in the vault, consume in the repo.

You author the brain in the Obsidian vault (OneDrive). AI tools consume it in a code repo (efficio-orbit), where it's exported. Run Codex / Claude in the repo, never in the vault. The brain describes Orbit's real components, which live in the @efficio/orbit package — so a project needs that package to build real UI.

PART 1

One-time setup: get the brain into the codebase

do once per repo · re-run on change
1

Open Terminal.

2

Dry-run first (writes nothing — preview)

# run from the vault
cd "~/Library/CloudStorage/OneDrive-Efficio/Orbit Design Brain"
python3 tools/export_brain.py --target <path-to-efficio-orbit> --profile all --dry-run
3

Run it for real — drop --dry-run

python3 tools/export_brain.py --target <path-to-efficio-orbit> --profile all
4

What it writes into the repo

AGENTS.md + CLAUDE.md at the root; design-brain/, _benchmarks/, _review/ under it; .claude/skills + the design-reviewer agent; a DESIGN_BRAIN_EXPORT.md notice.

5

Commit & push in efficio-orbit

So every teammate gets the brain via git pull. Profiles: all (Codex + Claude), codex (AGENTS.md + reference layer), claude (adds CLAUDE.md + .claude/), lovable (projections only).

CASE A

A new feature / screen in Orbit

the common case · no new repo
1

Open efficio-orbit in your AI tool

Codex: run codex from inside the folder. Claude Code: open the folder.

2

Confirm it loaded the brain

Ask: "Before writing code, summarise the Orbit constraints you'll follow." It should mention tokens-only, platform-first, the Definition of Done. If not — wrong folder, or not exported.

3

Give the task — and name the platform

e.g. "Build a Connected Platform workspace card for X." If it's an assigned sprint feature: "…following discovery/<initiative>.md."

4

Let it build to spec

It reads the relevant design-brain/ files (routing table in AGENTS.md §3): the platform profile, defaults.md, the component / pattern contract. Tokens only, real components, defaults, the pattern composition.

5

Validate against the Definition of Done

All states, both themes, both densities, WCAG 2.2 AA, copy, motion, no anti-patterns (AGENTS.md §5). For a thorough pass, ask it to run the design-reviewer — a blocker means not done.

6

Feed back to the vault

If it gets Orbit wrong and you fix it, update the vault file (in Obsidian) — not just the output, not the exported copy — then re-export (Part 1).

CASE B

A brand-new, separate repo / app

1

Create or clone the new repo.

2

Make @efficio/orbit available in it

The brain references Orbit's package, so the project needs it: npm install @efficio/orbit (if published), or a workspace / linked dependency from your efficio-orbit checkout. If Orbit isn't installable yet, the brain still guides structure/behaviour, but imports won't resolve — flag it to the design-system owner.

3

Export the brain into the new repo

cd "~/Library/CloudStorage/OneDrive-Efficio/Orbit Design Brain"
python3 tools/export_brain.py --target /path/to/new-repo --profile all
4

Commit it in the new repo.

5

Open Codex / Claude in the new repo

It auto-loads AGENTS.md → same usage as Case A, steps 2–5.

6

Feed back to the VAULT, not the repo copy

Corrections always go to the canonical vault, then re-export to every repo that uses the brain. You can target as many repos as you like.

RULES

Gotchas — don't skip

📝
Edit the vault, never the copiesRepo copies are generated; hand-edits get overwritten and cause drift.
🔁
Re-export after vault changesTo each repo that uses the brain. (CI drift-check is on the roadmap.)
📂
Run AI in the repo, not the vaultThe vault is Obsidian-only authoring.
📦
The brain needs @efficio/orbitWithout it, you get guidance with nothing to import.
✅
Verify the brain loadedAsk the AI to summarise the constraints before trusting output.
🟪
Lovable is separateIt can't read the repo — paste design-brain/lovable/, or connect the Enterprise design system.
